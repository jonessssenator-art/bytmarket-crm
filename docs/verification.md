# Проверка предкодового пакета

Дата: 05.11.2026. Объект проверки - документы и прототипы, не действующая CRM.

## Исходный ориентир
Print 360 доступен через авторизованный GitHub CLI, закрытый репозиторий. Проверен commit `657b1fb62f47af71443c3788904173843a2bc155`, исходная копия не изменялась. Отдельный локальный запуск и просмотр экрана владельца выполнены. README подтверждает демонстрационный режим без настоящей базы; код и зависимости не перенесены в БытМаркет.

## Документы
Три агента подготовили отраслевой анализ, архитектуру/приёмку и рабочие сценарии/права. Основной агент сверил пакет с ответами пользователя. Независимая проверка выявила и устранила: разные резервы одного учебного SKU; безусловное откладывание 1С; утверждение о выбранном режиме сканера; отсутствие явного реестра девяти результатов. Уточнения ООО/ИП, внутренних уведомлений и бумажного старта внесены в документы.

Есть явная карта всех 19 разделов ТЗ в requirements-map.md. Новые бизнес-показатели, фактические потери, клиенты и сроки разработки не выдумывались. Официальные источники и ограничения их проверки приведены в research-trade.md.

## Прототипы
- Playwright в реальном Chromium: 8 рабочих мест при 1440x1000 и 390x844, всего 16 снимков.
- Проверено отсутствие горизонтального переполнения всей страницы. Найдено переполнение продавца при 390px; исправлено ограничением ширины элемента сетки и повторно проверено. Широкие таблицы прокручиваются внутри контейнера.
- Визуально просмотрены все восемь desktop-рабочих мест, мобильные владелец, продавец, представитель и курьер. Остальные мобильные снимки созданы и проверены на переполнение; полный ручной визуальный аудит этих четырёх экранов не заявляется.
- Manrope 400/600/700 с локальной кириллицей/латиницей загружен; логотип отображается без растяжения. Лицензия шрифта сохранена рядом с файлами.
- Проверены переключение роли, вкладка «Требует внимания», подробности сигнала, закрытие диалога клавишей Escape, состояние без данных, поиск/фильтрация строки, пояснение оплаты, горизонтальная прокрутка мобильной навигации. Эти проверки прошли.
- Во время прохода по 16 экранам не зарегистрировано ошибок JavaScript. Первоначальный 404 favicon устранён встроенной пустой иконкой.
- Отдельный UX-агент просмотрел владелец/продавец desktop и представитель/курьер mobile. Вердикт **ship для показа предкодовых макетов**, не для запуска продукта. Отмеченная доступность прокрутки мобильной навигации затем проверена в браузере.
- Создан самодостаточный HTML с встроенными шрифтами/логотипом/CSS/JS; проверены открытие локального файла, переключение роли, загрузка логотипа и отсутствие переполнения на мобильной ширине.

## Что не проверено и не реализовано
Сервер, БД, авторизация и разграничение реальных данных; проведение продаж/оплат/склада; импорт/экспорт; сохранение черновиков; реальные документы и фискализация; 1С/ККТ/маркировка/банк/ЭДО; рабочие уведомления; резервное копирование/восстановление; многопользовательская конкурентность; нагрузка на 1000 SKU; полное тестирование скринридером и физическим оборудованием. Сценарии A01-A33 - план, не выполненные тесты.

Прототип содержит только учебные примеры и пояснения. Публичная публикация и серверное развёртывание не выполнены. Реальные реквизиты и данные клиентов не получены и не загружались.
