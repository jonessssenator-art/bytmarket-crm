# Доработка рабочего контура по ТЗ

Статус обновления 05.11.2026: основные сценарии ниже реализованы. Проверки, границы и оставшиеся пункты исходного ТЗ перечислены в runtime-status.md. Интерфейс сохранён на настоящих компонентах Print 360.

05.11.2026. Источник: 19 разделов ТЗ, ответы владельца и проверенный runtime-status. Касса и 1С исключены пользователем; клиентское приложение, сложные акции и оптимизация маршрута остаются поздними этапами исходного ТЗ. Стиль существующих таблиц и форм сохраняется. Навыки synthesize-research и write-spec применены к уже собранному брифу, повторного интервью нет.

| Подтверждённая потребность | Ответственный / процесс | Реализация | Данные и критерий |
|---|---|---|---|
| Блокнот, начальные долги | Бухгалтер / перенос | Документ начального долга и погашения, импорт с проверкой | Остаток сверяется с исходным документом, не создаётся фиктивная продажа |
| Частичные поставки и расхождения | Склад / приёмка | Фактические количества, принятый брак, недопоставка, закрытие остатка | Два прихода одной закупки не превышают заказ; в долг входит фактически принятое |
| Расчёты с поставщиком | Бухгалтер / выплаты | Оплаты поставщикам, сроки, сверка | Долг = принятый товар - возвраты - распределённые выплаты |
| Пересчёт товаров | Склад / инвентаризация | Снимок, фактические количества, проведение | После изменения остатков снимок нельзя провести незаметно |
| Возврат поставщику | Склад / возвраты | Возврат по партии, недоступность зарезервированного | Остатки и взаиморасчёты изменяются одной транзакцией |
| Условия опта и скидки | Менеджер / цена | Индивидуальные цены, лимиты скидок и маржи, согласование версии заказа | Изменение заказа аннулирует согласование; история цены неизменна |
| Не забывать клиента | Менеджер / задачи | Контакты, точки, задачи, история, планы | Представитель видит свои записи; задачи сохраняются |
| Подбор закупки | Владелец / запас | Предложения с доступным запасом, ожидаемыми поступлениями и упаковкой | Формула раскрыта, без истории нет выдуманного прогноза |
| Финансовый контроль | Владелец / отчёты | Товары, клиенты, сотрудники, акции, доставка, сравнение периодов | Итоги раскрываются до документов; одна продажа имеет одного ответственного за результат |
| Минимум действий | Все / таблицы | Сортировка, страницы, сохранённые представления, итоги | Экспорт и представление не расширяют серверные права |
| Документы и доступ | Владелец / обслуживание | Аудит, снимки документов, роли и ограничения, внутренняя сводка | Изменённые реквизиты не переписывают старый документ |

Неизвестные внешние каналы, учётная политика, независимое резервное хранилище и сервер для доступа сотрудников не подменяются демонстрацией. Налоговые документы ООО -> ИП и фактическая маркировка требуют согласованных данных/оборудования. Внутренние процессы разрабатываются независимо от этих подключений.
