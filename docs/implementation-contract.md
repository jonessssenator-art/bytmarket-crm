# Контракт первой рабочей реализации

05.11.2026: пользователь разрешил отложить кассу/1С, запросил реальную CRM с сохранением. Реализация: React + Node 24 HTTP API + node:sqlite DatabaseSync. Один процесс сервера, одна локальная SQLite-БД, WAL, foreign_keys, BEGIN IMMEDIATE для каждой учётной команды. PostgreSQL/Nest из предкодовой спецификации остаются предложением для последующего серверного масштаба, не скрытой зависимостью локального запуска. Внешняя фискализация никогда не имитируется.

## API и форматы
Все пути /api/v1. Ответ - JSON объект или массив напрямую, ошибка {error:string,code?:string}. ID UUID strings; money *_cents целые копейки, qty базовые штуки. Даты ISO/date strings. entity_id: организация, warehouse_id: физический склад. Роли owner,seller,manager,rep,accountant,warehouse,dispatcher,courier. user.roles массив строк, entity_ids массив, warehouse_ids массив. owner вседоступен; остальные scoped. Никаких пользовательских demo-role switches.

GET /auth/status -> {needs_setup:boolean}; POST /auth/setup {name,email,password} -> {user,csrf}; POST /auth/login {email,password} -> {user,csrf}; GET /auth/me -> {user,csrf}; POST /auth/logout. HttpOnly session cookie. Mutations X-CSRF-Token, Idempotency-Key. First setup creates owner and default справочники ООО/ИП и склад при магазине, НЕТ товаров, остатков, клиентов/оплат.

GET /meta -> {entities,warehouses,users,settings,permissions}; сущности {id,name,kind,details}, склады {id,name}. Users endpoint owner-only full identities; meta exposes minimal relevant staff selectors.
GET/POST /users; PATCH /users/:id. POST /entities, PATCH /entities/:id, POST /warehouses. GET/PATCH /settings. Минимум опта null until configured (does not invent N), threshold 50. Entity policy ООО wholesale, ИП retail.

GET/POST /products; PATCH /products/:id. Product {id,sku,name,brand,category,barcode,unit,pack_size,retail_cents,wholesale_cents,min_stock,active,attributes,expiry_required,marked}. GET supports q,entity_id,warehouse_id; returned item has on_hand,reserved,available,quarantine; cost omitted without financial rights. POST /products/import/preview {rows:[product...]}; POST /products/import {rows,preview_hash}. Numeric validation, no duplicates, atomic apply.
GET/POST /clients; PATCH /clients/:id. Client {id,name,kind,phone,email,address,inn,assigned_to,credit_limit_cents,term_days,notes,contacts,addresses}. List scoped rep/manager own assigned. Supplier represented client kind supplier.

GET /stock?entity_id&warehouse_id -> rows {product_id,sku,name,on_hand,reserved,available,quarantine,...}; GET /stock/movements. POST /stock/receive {entity_id,warehouse_id,product_id,qty,cost_cents,reason,batch_number?,expires_at?,supplier_id?}; POST /stock/adjust {entity_id,warehouse_id,product_id,qty,reason} qty signed; POST /stock/transfer {entity_id,warehouse_id,to_warehouse_id,product_id,qty,reason}; POST /stock/release {entity_id,warehouse_id,product_id,qty,reason} quarantine->usable. Legal entity never changes through transfer.

GET/POST /orders; GET/PATCH /orders/:id. Draft {entity_id,warehouse_id,client_id?,channel:retail|wholesale,lines:[{product_id,quantity,unit:piece|box,discount_percent?}],notes?,fulfillment:pickup|delivery,address?,due_date?}. Server calculates snapshots, integer base qty, pack factor, price; PATCH draft only, version conflict. GET item {id,number,status,total_cents,paid_cents,refunded_cents,returned_cents,shipped_cents,client_name,lines,...}. Line {id,product_id,name,sku,qty,unit_factor,unit_price_cents,line_total_cents,shipped_qty,returned_qty,cost_cents}. POST /orders/:id/confirm; /cancel; /ship {lines?:[{line_id,qty}]} default full remainder; /return {lines:[{line_id,qty}],reason}; /repeat -> new draft with current quote + changes. Retail immediate sequence through confirm/payment/ship, no fake fiscal status. Print order/invoice uses actual snapshots, entity details, pending legal fields visibly incomplete.

Finance extension:
GET/POST /payments; POST accepts {entity_id,client_id?,order_id?,amount_cents,method:cash|bank,allocations?:[{order_id,amount_cents}],collected_by?,reference?,note?}. Confirmed manual record with actor and explicit evidence; cash courier/rep increases custody, handover separate. GET /cash -> {balances:[{user_id,name,entity_id,amount_cents}],handovers:[...]}; POST /cash/handovers {entity_id,amount_cents,note}; POST /cash/handovers/:id/confirm. GET/POST /expenses {entity_id,amount_cents,category,note,date}; POST /refunds {order_id,amount_cents,method,reason}. GET /reports/overview?entity_id&from&to -> {sales_cents,cost_cents,gross_profit_cents,receipts_cents,debt_cents,overdue_cents,inventory_cents,expenses_cents,returns_cents,writeoffs_cents,cash_custody_cents,has_data,products,documents}. Reports by entity, no naive consolidation.
GET /alerts -> [{id,entity_id,warehouse_id,product_id,name,available,threshold,status,read_at,created_at}]; POST /alerts/:id/read. stock commands refresh episodes in their transaction. GET /audit owner/accountant only.
GET/POST /deliveries {order_id,courier_id?,address,phone,interval,note,places}; PATCH /deliveries/:id {courier_id?,status,note?,reason?}. status awaiting|assigned|in_transit|delivered|failed. Courier only assigned. No delivered=>payment.
GET/POST /visits {client_id,scheduled_at,note}; PATCH /visits/:id {status,result,reason,next_date}; rep own. GET/POST /purchases {entity_id,warehouse_id,supplier_id?,expected_at,lines:[{product_id,qty,cost_cents}],notes}; POST /purchases/:id/receive -> delegates core receive inside transaction; tracks purchase status draft|ordered|received; no receipt double effect.
GET/POST /promotions {name,starts_at,ends_at,discount_percent,product_ids}; server order pricing applies active eligible simple promo, no stacking automatic manual discount. Only owner creates.

## Shared server context (for module implementation)
server/db.mjs exports createDb(path) returning DatabaseSync migrated core tables. server/core.mjs exports registerCore(add,ctx), helpers created on ctx by function installCore(ctx). server/extensions.mjs exports initExtensions(db), registerExtensions(add,ctx). Core server index initializes core schema -> initExtensions -> installCore -> routes. ctx has db, tx(fn) sync begin immediate/commit/rollback (nested tx reuses outer), id(), now(), error(status,message), requireRole(user,...roles), scope(user,entityId,warehouseId?), audit(user,action,type,id,payload), stockReceive(user,body), refreshAlerts(entity,warehouse,product), canOrder(user,order), orderView(user,id). add(method,path,handler,{public?:true}) handler receives {user,body,params,query,req,session}, returns JSON; auth may set response cookies via req/res exposed.
Core tables fixed: entities(id,name,kind,details JSON text), warehouses(id,name), users(id,name,email,password_hash,roles JSON text,entity_ids JSON text,warehouse_ids JSON text,active,created_at), clients(id,name,kind,phone,email,address,inn,assigned_to,credit_limit_cents,term_days,notes,contacts JSON text,addresses JSON text,created_at), products(id,sku,name,brand,category,barcode,unit,pack_size,retail_cents,wholesale_cents,min_stock,active,attributes JSON text,expiry_required,marked,created_at), inventory(entity_id,warehouse_id,product_id,on_hand,reserved,quarantine,cost_cents) PK triple, stock_movements(id,entity_id,warehouse_id,product_id,qty,kind,reason,order_id,actor_id,created_at,cost_cents), orders(id,number,entity_id,warehouse_id,client_id,channel,status,total_cents,paid_cents,refunded_cents,returned_cents,shipped_cents,notes,fulfillment,address,due_date,created_by,created_at,updated_at,version), order_lines(id,order_id,product_id,name,sku,qty,unit_factor,unit_price_cents,line_total_cents,shipped_qty,returned_qty,cost_cents), alerts(id,entity_id,warehouse_id,product_id,available,threshold,status,read_at,created_at,resolved_at), audit(id,actor_id,action,object_type,object_id,payload,created_at), settings(key,value JSON text). Extensions own their extra schema. Any needed change coordinate before modifying shared contract. Prefer nullable metadata vs incompatible schema redesign midstream.
