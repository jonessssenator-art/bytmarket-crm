# Статус рабочей CRM

Обновлено 05.11.2026. Описывает код `server/` и `web/src/`, а не обещания из исходного ТЗ. Касса и 1С исключены из текущей разработки по указанию пользователя. Интерфейс использует перенесённые компоненты Print 360, commit `657b1fb62f47af71443c3788904173843a2bc155`; происхождение в `web/src/print360/PROVENANCE.json`.

## Данные и эксплуатация

Node.js 24, SQLite WAL, единый API, транзакции и ключи идемпотентности. Суммы в целых копейках, количества в штуках. Рабочая база `data/bytmarket.sqlite`, сервер `http://127.0.0.1:3000`. После обновления сохранена существующая учётная запись владельца. В рабочую базу не загружались тестовые товары, клиенты, продажи и платежи. Доступ владельца сохранён в локальном приватном файле `data/Доступ владельца.txt`.

Обновление добавляет таблицы без очистки существующих данных. Для старых полностью принятых закупок создаётся история приёмки и обязательство поставщику без повторного прихода товара. Новая схема содержит 43 таблицы. Перед обновлением и после запуска созданы проверенные резервные копии. Целостность рабочей базы: `ok`; количество исходных пользователей и торговых документов не изменилось.

## Что работает

| Раздел | Реализованные сценарии |
|---|---|
| Продажи | Черновики с автосохранением на устройстве, серверная цена, резерв, частичная отгрузка, отмена остатка, повтор с пересчётом цены и доступности. Оплата, сборка, отгрузка и доставка раздельны. |
| Единицы | Штука, упаковка и коробка с отдельными коэффициентами. В строке сохраняются количество, коэффициент, цена и скидка. Изменение каталога не переписывает проведённую историю. |
| Каталог | SKU, бренд, категория, группа, объём, вес, аромат, фото JPG/PNG/WebP до 400 КБ, основной штрихкод, активность, срок годности, признак маркировки, порог остатка. Фото загружается отдельно от списка каталога. |
| Цены | Розничные, оптовые и индивидуальные цены по клиенту и организации; процентные акции; наибольшая из акции и ручной скидки без суммирования. Индивидуальная цена заменяет базу. |
| Согласования | Лимиты ручной скидки по ролям и минимальной маржи. Согласование цены и исключительной отгрузки владельцем связано с версией заказа. Изменение заказа/оплаты требует нового решения. |
| Отсрочка | Проверка срока, лимита, начального долга и просроченных заказов перед отгрузкой. Дата оплаты вне согласованного срока требует исключения владельца. |
| Клиенты | Контакты, несколько торговых точек, выбор точки в доставке, закрепление сотрудника, кредитные условия, индивидуальные цены, задачи и история заказов. |
| Представитель | Свои клиенты и визиты, результат визита, заказ из истории, приём наличных, задачи и личный план. Черновик без сервера не создаёт резерва. |
| Склад | Приход, партии, резерв, отпуск, перемещения в пределах собственника, списание, карантин, проверка возврата. Нельзя одновременно продать последнюю единицу. |
| Инвентаризация | Снимок партий, резервов и себестоимости, ведомость фактических годных/карантинных остатков, проведение бухгалтером/владельцем, отмена черновика. Изменившийся снимок отклоняется. Результат фиксируется движением и аудитом. |
| Закупки | Заказ поставщику, несколько частичных приёмок, причины расхождений, карантин при приёмке, закрытие недопоставленного остатка с причиной. Принятое количество не превышает заказ. |
| Поставщики | Регистр обязательств по фактически принятому товару, начальный долг, фактические выплаты, возврат аванса, возврат товара по незарезервированной партии. Переплата одного поставщика не скрывает долг другому на экране владельца. |
| Предложения на закупку | Продажи за 30 дней, доступность, резерв, ожидаемые поставки, срок поставки, минимальный запас и округление до упаковки. Решение о закупке принимает сотрудник. Нет истории - нет выдуманного прогноза. |
| Деньги | Частичные/смешанные оплаты, несколько оплат заказа, разнесение неопознанного остатка, возвраты, расходы, наличные у представителя/курьера и сдача другому сотруднику. Доставка не создаёт оплату. |
| Начальные долги | Отдельный документ по записи блокнота и его частичное погашение. Погашение входит в поступления, но не в продажи; его нельзя повторно разнести на заказ. Остаток включён в общий долг и расшифровку. |
| Доставка | Самовывоз/доставка, адрес, телефон, интервал, места, назначение курьера, статусы и причины неудачи; оплата при вручении отдельным признаком. Дедлайн и факт доставки, стоимость клиенту и аналитические затраты. |
| Документы | Печатные формы счёта, реквизитов и отгрузки; PDF через печать браузера. Снимок реквизитов и состава связан с версией заказа. Нельзя сформировать отгрузку без отгруженного товара. Это не фискальные или подписанные электронные документы. |
| Аналитика | Продажи/возвраты по движениям, себестоимость, валовая прибыль, деньги, долги и просрочка, остатки, списания. Разрезы товаров, категорий, брендов, клиентов, сотрудников и акций раскрываются до движений. Личный результат относится только автору заказа. |

| Операционные отчёты | Сопоставимый предыдущий период, активность и интервал покупок клиентов, текущий долг, запас в днях, последние отгрузки, наблюдаемые дни без остатка, доставки и задержки. |
| Требует внимания | Низкий остаток, срок годности, товар без отгрузки 60 дней, просрочка, задержка сборки/отгрузки, ожидающие согласования, задачи к сроку. У каждого сигнала есть основание и переход в раздел. |
| Сводка владельцу | Одна внутренняя сводка в день за предыдущий день. Предложение по умолчанию: 09:00 Астрахань; час и включение настраиваются. Формируется при работающем сервере, без внешних сообщений. |
| Права | Восемь совмещаемых ролей, организации и склады. Дополнительные ограничения закупочных цен, чужих клиентов, изменения каталога, скидок, списаний, возвратов и кнопок экспорта. Серверные права меняются и для открытой сессии. |

## Важные определения и границы

- День отчёта - Europe/Astrakhan, UTC+4. Серверные интервалы включают начало и исключают конец; в календарных полях пользователь задаёт обе даты включительно.
- Неизвестная себестоимость не заменяется нулём. Валовая прибыль не объявляется чистой прибылью; налоги и нераспределённые затраты требуют учётной политики.
- Индивидуальная цена действует в выбранной организации. Минимальную маржу по неизвестной себестоимости автоматически подтвердить нельзя.
- Возврат в карантин и возврат денег независимы. Возврат поставщику уменьшает запасы и обязательство одной транзакцией.
- Уведомление по умолчанию: доступно строго меньше 50 штук. Один открытый сигнал на эпизод; прочтение не закрывает дефицит. Порог SKU можно менять.
- Запас в днях - оценка по продажам, не доказательство спроса. Дни без остатка показаны только для дней, в которые были наблюдения после запуска учёта; прошлое не выдумывается. Сравнение периодов не является причинной оценкой эффективности акции и не устраняет сезонность.
- Стоимость доставки пока информационна и не увеличивает товарный долг автоматически. Фактические расходы доставки бухгалтер отражает отдельно; сохранение аналитической суммы само по себе не является выплатой.
- Платежи поставщикам ведутся по общему сальдо контрагента, без автоматического разнесения по отдельным счетам поставки.
- Ограничение кнопок экспорта не предотвращает ручное копирование уже разрешённых сотруднику данных.

## Что ещё не закрыто исходным ТЗ

Обновление существенно расширяет рабочую версию, но не означает завершения каждого пункта большого исходного ТЗ:

- Отдельный регистр нескольких касс/банковских счетов и внутренних денежных переводов; сейчас методы cash/bank и учёт наличных у сотрудников.
- Несколько штрихкодов одного SKU, сохранение именованных наборов фильтров таблиц, более детальные клиентские ограничения кратности заказа.
- Расширенный анализ совместных покупок, товарных возможностей клиента, эффекта акций с учётом наличия/сезонности; история повторных попыток доставки и частичное вручение (пока не включено).
- Автоматический обмен ООО -> ИП не внедрён: нужны подтверждённые бухгалтером договорные и налоговые правила. Остатки двух собственников не смешиваются.
- Внешняя отправка документов не подключена: канал не выбран. Подготовка документа и печать работают, отправка не имитируется.
- Размещение для сотрудников на общем HTTPS-сервере, независимое резервное хранилище, заполнение реальных реквизитов и ввод проверенных данных блокнота, обучение и пилот требуют фактических данных/инфраструктуры владельца.

Касса, 1С, ЭДО и проверка маркировки оборудованием не подключались. Клиентское приложение, прогнозирование, маршрутизация и сложная лояльность остаются поздними этапами исходного ТЗ.
