# Постоянное размещение CRM

Публичный репозиторий содержит код, но не рабочую базу и не пароли. GitHub Pages не запускает Node.js и SQLite. Для общей базы нужен отдельный сервер или сервис контейнеров с постоянным диском. Туннель с ноутбука не является постоянным размещением.

## Подготовлено

- Dockerfile: Node.js 24, сборка React, непривилегированный процесс, проверка состояния.
- compose.yaml: один экземпляр, перезапуск после сбоя/перезагрузки сервера, постоянный каталог данных. Порт 3100 доступен только самому серверу.
- Сжатие ответов gzip; интерфейс и API обслуживаются одним источником.
- В демонстрационном режиме открытие ссылки сразу создаёт сессию владельца. В меню доступен переключатель восьми ролей. Серверные ограничения роли остаются действующими.
- Контрольная копия при запуске, каждые 6 часов и при корректной остановке.

## Развёртывание изолированной демонстрации

1. Выбрать доступный сервер и домен. Нужны Docker Compose, свободные порты 80/443 для HTTPS-прокси и постоянный диск. Не менять конфигурацию чужих сайтов на сервере.
2. Скопировать проверенную **отдельную демонстрационную** SQLite-базу в `data/hosting-demo/crm.sqlite`. Использовать SQLite backup API или штатный скрипт копирования, а не копировать работающий файл без WAL. Не коммитить базу в GitHub.
3. На машине с Node.js 24 подготовить роли:

   ```sh
   node scripts/enable-demo.mjs --isolated-demo --db data/hosting-demo/crm.sqlite
   ```

4. На Linux передать каталог данных UID/GID 1000 контейнера и ограничить доступ:

   ```sh
   sudo chown -R 1000:1000 data/hosting-demo
   sudo chmod 700 data/hosting-demo
   docker compose up -d --build
   ```

5. Настроить HTTPS-прокси на `127.0.0.1:3100` с сохранением исходного `Host`. `SECURE_COOKIES=1` требует HTTPS снаружи. Не публиковать папку данных веб-сервером.
6. Проверить ссылку в чистом браузере, переключение владельца и курьера, создание заказа и сохранение после перезапуска контейнера. Скопировать проверенную резервную копию в отдельное хранилище. Копии на диске сервера не защищают от потери самого сервера.

`DEMO_MODE=1` действует только при наличии заранее подготовленного реестра `demo_access`. Обычная база без него не запустится в режиме без паролей. При `DEMO_MODE=0` обычная авторизация остаётся обязательной. Демонстрация общая для всех посетителей: изменения одного посетителя увидят остальные, поэтому в ней должны быть только тестовые данные.

## Что ещё требуется

Доступный хостинг/сервер и HTTPS-адрес. Наличие Dockerfile и успешная сборка не означают, что CRM уже размещена в интернете. Текущая локальная демонстрация продолжает зависеть от Mac до фактического переноса.
