# БытМаркет CRM

Локальная CRM для рознично-оптовой торговли бытовой химией. React-интерфейс, сервер Node.js 24 и SQLite. **Рабочие данные сохраняются на сервере в `data/bytmarket.sqlite`, а не только в браузере.** Каталог и документы при первом запуске пустые. Учебный дизайн-проект в `design/` хранится отдельно и не используется для учёта.

## Запуск

На этом Mac можно открыть файл **«Запустить CRM.command»** двойным щелчком. Он собирает интерфейс, запускает сервер и открывает браузер. Окно запуска нужно оставить открытым.

Нужен Node.js 24 или новее. Для запуска из терминала:

```sh
npm ci
npm run build
npm start
```

Откройте **http://127.0.0.1:3000**. При первом входе создайте владельца. Первичная настройка доступна с самого компьютера, на котором запущен сервер. Готовых паролей нет.

Сервер работает, пока запущен процесс `npm start`. Перезапуск не удаляет данные. Для разработки интерфейса отдельно запустите `npm run dev`; Vite на порту 5173 обращается к серверу на порту 3000.

Переменные окружения передаются процессу, `.env.example` служит образцом и автоматически не загружается:

```sh
DB_PATH=/полный/путь/bytmarket.sqlite BACKUP_DIR=/путь/к/копиям npm start
```

По умолчанию доступ локальный. Для сотрудников на других устройствах нужен постоянно работающий сервер, адрес и HTTPS. GitHub Pages не запускает серверную CRM; частная база, код исходного Print 360 и клиентские данные публично не опубликованы.

## Первичная настройка

1. Создайте владельца, заполните действительные реквизиты ООО и ИП.
2. Укажите минимальное количество штук в оптовом заказе. Пока оно не задано, оптовый заказ можно сохранить, но нельзя подтвердить.
3. Создайте сотрудников с ролями и доступом к нужным организациям и складам. При необходимости добавьте второй склад.
4. Добавьте товары вручную или загрузите CSV после предварительной проверки. Разные ароматы и объёмы - отдельные товары. Укажите число штук в коробке и цены.
5. Внесите результаты инвентаризации приходом по фактическому владельцу товара, складу и партии. Если закупочная стоимость неизвестна, оставьте её незаданной: отчёт покажет неполные данные.
6. Внесите покупателей и поставщиков. Для отсрочки заполните срок и кредитный лимит клиента; у заказа нужна дата оплаты.
7. Проверьте одну настоящую продажу и сверку с бухгалтером, затем обучите сотрудников на их рабочих местах.

ООО и ИП имеют раздельные остатки и расчёты. Перемещение между складами не меняет владельца товара. Автоматическая передача ООО -> ИП не включена: её документы и налоги пока не определены. Начальные долги из блокнота требуют отдельной сверенной загрузки; не создавайте фиктивные продажи для их имитации.

## Реализованный контур

- Учётные записи, серверная проверка ролей и областей доступа, журнал изменений.
- Товары, упаковки, цены, клиенты, реквизиты, проверка импорта CSV.
- Черновик заказа, подтверждение с резервом, частичная отгрузка, отмена остатка, повтор с пересчётом цены, товарный возврат в карантин.
- Приход, партии и сроки годности, перемещения между складами, корректировки с основанием, проверка возвращённого товара.
- Заказы поставщикам и приёмка, простые процентные акции.
- Ручная фиксация фактических платежей, частичные оплаты, распределения, возвраты денег, расходы, несданные наличные и подтверждение их передачи другим сотрудником.
- Визиты представителя, назначение доставки, результаты работы курьера. Доставка сама по себе не создаёт оплату.
- Базовые отчёты по отгрузкам и возвратам, закупочной стоимости, задолженности, поступлениям денег и товарам. Неизвестная себестоимость обозначается явно. Чистая прибыль не рассчитывается.
- Уведомления владельцу внутри CRM при доступном остатке ниже порога товара; по умолчанию 50 штук. Повторное обновление не создаёт второе уведомление по той же нехватке.
- Печать внутренних документов, экспорт таблиц в Excel, резервные копии.

Сервер повторно проверяет цену, упаковку, наличие и права. Операции записи выполняются транзакционно, идентификатор запроса защищает от повторного создания документа/платежа. Денежные суммы хранятся целым числом копеек. Коробка фиксирует коэффициент в строке документа, последующее изменение карточки не меняет проведённую историю.

## Что намеренно не выдаётся за подключённую функцию

ККТ, фискальные чеки, эквайринг, банк, 1С, ЭДО и внешняя отправка документов **не подключены**. Зафиксированный в CRM платёж не является фискальным чеком. Приём маркированного товара помещает его в карантин; продажа блокируется до реализации согласованного процесса маркировки.

Это первая рабочая версия, а не выполнение всех последующих этапов большого ТЗ. Индивидуальные цены, согласования исключений, полная аналитика планов/сезонности/оборачиваемости, расширенная приёмка с расхождениями, частичное вручение, клиентское приложение и бухгалтерские регистры требуют дальнейшей разработки. Точные ограничения текущих операций см. в [статусе реализации](docs/runtime-status.md).

SQLite выбран для одного серверного процесса и небольшого стартового контура. Нельзя размещать рабочий файл базы на сетевой папке и запускать несколько независимых экземпляров приложения над ним. Для распределённого размещения предусмотрен переход на серверную СУБД с миграцией и проверкой учёта.

## Копии и восстановление

`npm start` делает проверенную копию при запуске, каждые 6 часов работы и при корректной остановке. По умолчанию копии лежат в `backups/` на этом же компьютере. Это защищает от части ошибок, но не от утраты самого компьютера. Для независимой копии настройте резервное хранилище и регулярное перенесение файлов `.sqlite` вместе с `.json`.

Создать копию вручную:

```sh
npm run backup
```

Проверить восстановление в отдельную временную БД без изменения рабочей:

```sh
npm run restore-check -- backups/имя-копии.sqlite
```

Проверяются контрольная сумма, целостность SQLite, связи и количество записей; восстановленная база открывается для записи. Копирование использует штатный SQLite backup API и включает подтверждённые записи WAL.

Для реального восстановления: остановите сервер, сохраните текущую папку `data` отдельно, скопируйте проверенную копию под **новым именем**, запустите с `DB_PATH=/путь/к/восстановленной.sqlite`, проверьте документы и остатки. Не подменяйте файл работающей базы и не смешивайте его со старыми `-wal`/`-shm`. Возврат к копии теряет операции после её даты; их нужно сверить отдельно.

## Проверки

```sh
npm test
npm run build
```

Тесты создают изолированные временные базы, не изменяют рабочий каталог и не добавляют демонстрационных покупателей. Проверки интерфейса и результаты приёмки рабочей версии фиксируются в `docs/runtime-status.md`.
